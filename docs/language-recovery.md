# 界面语言资源恢复

此功能修复的是应用界面翻译资源缺失／损坏，不负责下载Apple Vision的OCR模型。正常安装包已包含9种界面语言。

## 启动与修复

1. 启动校验语言资源。完整资源可正常使用；缺包、缺少某个语言或内容不匹配时，尝试当前版本已校验的用户资源缓存，再回退到代码内置英文。运行路径不调用会fatalError的SwiftPM `Bundle.module`。
2. 缺资源时只弹一次原生提示。选择“稍后”仍可使用应用；“下载并修复”或“安装已下载语言包”会打开设置的修复区域。也可在“设置 → 关于 → 语言资源”手动修复。
3. **仓库为私有时**：应用不读取或内置GitHub凭据。匿名请求无法访问时，提示通过浏览器登录GitHub下载对应JSON，再用“安装已下载语言包”导入。浏览器登录、文件选择仍需用户完成；不声称私有仓库支持匿名一键安装。
4. 将来只更改仓库为公开，现有下载地址便可直接工作。下载只在用户点击后发起，没有后台探测、统计或自动下载。网络失败仍可使用英文。
5. 修复只写`~/Library/Application Support/PasteIt/LanguagePacks/<SHA256>.bundle`。校验成功才替换语言缓存，不修改`.app`、签名、偏好、快捷键、历史、附件或系统权限。安装后重新打开应用以完整刷新现有窗口／菜单文字。

## 完整性与版本

语言包是纯翻译JSON，不包含脚本／程序／归档路径。应用内固定版本、build及SHA-256，拒绝损坏包、其他版本、超限文件、意外下载地址；仅允许HTTPS GitHub／raw.githubusercontent.com及受限重定向。下载使用不存Cookie或凭据的临时会话，最大2 MiB。用户缓存校验9种语言的完整文本摘要；安装拒绝目录链接，写入先在隔离目录完成后再替换，失败保持英文与原数据。

`python3 scripts/generate-localizations.py`同时生成语言包及编译清单。`python3 scripts/generate-language-pack.py --check`检查生成文件是否同步。语言包存放`Resources/LanguagePacks/<SHA256>.json`，源码与生成清单一并提交；已发布的旧包须保留，避免旧版本修复链接失效。

推荐打包脚本会在编译前检查清单，并在签名前逐语言检查实际App内的翻译；缺失或过期立即中止。版本发布脚本在提升版本后重建语言包并提交清单；本机验收不运行发布流程。

若`.app`被破坏且macOS在程序运行前拒绝签名，应用无法先弹框，应重新安装完整App。恢复不绕过系统签名保护。

## 验证

自动测试使用临时目录与合成数据，覆盖缺包回退、校验与版本拒绝、修复缓存损坏、配置与历史保留、私有下载提示及下载地址限制。显式`--ui-review-language-repair-only --recovery-pack-file /absolute/pack.json`仅在合成UI模式中使用；在临时副本移除资源后重新ad-hoc签名，验证英文启动、原生提示和恢复。不得删除已安装App资源来测试。
